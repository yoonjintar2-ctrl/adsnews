# AI 4대장의 썰전 (2026-10-03부터, '토론'에서 이름·방식 변경)

발행인 피드백(10/3): "갑자기 다른 주제가 나오고 둘끼리만 대화하는 느낌. 주제를 이어 가야 한다. 관심 있는 두 명이 계속 이어 가다가 끝날 때쯤 다른 사람이 등장해 이어 가는 방식은 좋다. 토론보다 '썰전'으로."

- **오늘의 썰 하나**를 정하고(질문 한 줄), 모든 줄이 그 썰에 머문다. 새 주제 꺼내기 금지.
- **바로 앞 줄을 받아서** 말한다(앞사람 말의 한 대목을 짚고 이어 가거나 맞받기). 번호로 상대를 지정하지 않는다.
- 구성(9~10줄): 그 캠페인에 가장 할 말이 많은 **두 사람**이 3번씩 주거니 받거니(1~6) → 끝날 무렵 **세 번째 사람이 '등장'**해 같은 썰에 새 근거를 얹고(7) → 둘 중 하나가 받아치고(8) → **네 번째 사람이 등장**해 썰을 정리하며 한 방(9). 필요하면 마지막 한마디(10).
- 짝은 캠페인마다 고른다. 예) 구글 제미나이 광고 → 제민아(Gemini, 자기 집 광고)와 지필태(ChatGPT, 경쟁사) / X에서 터진 캠페인 → 김그록이 짝.
- 한 줄 40~80자, 말맛 있게(썰 푸는 말투, 존댓말 섞인 동료끼리). 사실은 브리핑 범위만. 사람·제작진 깎아내리기 X.
- debate.json 줄: {who, tag(썰·받기·맞받기·등장·정리), to:[바로 앞 사람], text}. 화면 제목은 "AI 4대장의 썰전", topic은 오늘의 썰(질문).
- 각자 자기 말은 자기가 쓴다. 금로동은 옮기기만 한다(명백한 출력 오류만 정리).

## (지난 방식) 릴레이 토론 — 10/2~10/3 오전
- 금로동 과장이 한 줄씩 차례로 돌린다. 매 차례 그때까지의 대화 전문을 넘기고, **지정된 상대의 말을 직접 짚어 받아치는 한 줄(60~90자)**을 받는다.
- 각자 자기 말은 자기가 쓴다. 금로동은 옮기기만 한다(명백한 출력 오류 — 같은 구절 중복 등 — 만 정리).
- 기본 순서: 1 금로동 주장 → 2 지필태 → 3 김그록 → 4 제민아 → 5 금로동 역공 → 6 지필태 → 7 김그록 → 8 제민아 → 마무리 넷(김그록·지필태·제민아·금로동, 40~70자).
- 자리(기본): 금로동 찬성/해석, 지필태 회의파(화제가 실제 선택으로 이어지나), 김그록 X 반응 근거·도발, 제민아 캠페인 족보로 반론.
- 사실 확인: X 인용은 링크가 없으면 따옴표 인용 금지. 출연자 배역 등은 기사로 확인.
- debate.json 각 줄: {who, tag(주장/반박/역공/재반박/마무리), to:[상대], text}. 화면에서 좌(금로동·김그록)·우(지필태·제민아)로 번갈아 놓이고 "→ 상대"가 붙는다.

## 제민아 대리(Gemini Gem) 다룰 때
- 메시지에 '목소리'라는 단어가 들어가면 "저는 텍스트 기반 AI…" 식으로 거절하거나 멈춘다 → '캐릭터 연기', '배우' 등으로 바꿔 쓴다.
- 같은 대화방에서 이어 묻는 질문은 자주 멈춘다 → 매번 새 대화(Gem 첫 화면)에서 묻는다.
- 웹 검색이 멈출 때가 많다 → "웹 검색 없이"라고 쓰고 필요한 자료는 확인해서 넘긴다.
- 전송 버튼·저장 버튼은 첫 클릭이 먹지 않을 때가 많다 → 두 번째 클릭 후 전송/저장 상태를 꼭 확인.
- 3.1 Pro가 멈추면 3.6 Flash로 바꾸면 빨리 답한다.
- 새 대화는 Gem 주소(gemini.google.com/gem/718081b08b62)로 이동해서 연다. 대화 안의 '새 채팅' 버튼은 가끔 Gem이 아닌 일반 Gemini(/app)로 간다 → 화면 위 'Gem 이름' 확인.
- 입력은 `document.execCommand('insertText')`로 넣는다(붙여넣기 이벤트는 안 먹음). 전송은 버튼 `aria-label="메시지 보내기"` 클릭 → 안 되면 입력창 클릭 후 Enter. 보낸 뒤 URL이 /gem/…/<대화ID>로 바뀌었는지 확인.
- 지필태 대리 토론은 프로젝트 '광고늬우스 - 지필태 기자' 안에 새 대화(Work 모드, 프로젝트 칩 확인)를 따로 열어 진행하면, '여기서 대화하기' 방의 그림 작업과 동시에 돌릴 수 있다.
